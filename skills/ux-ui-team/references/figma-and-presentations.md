# Figma, visibility, and presentations

Figma is supported, not mandatory for every web task. When requested, editable frames/slides, reference boards and review visibility are deliverables. Discover connector capabilities and load required Figma skills before creating files, authoring or reading design context. Never invent plugin APIs. If writes/renders are unavailable, provide the reviewable artifact and exact outstanding Figma work; no desktop/personal-browser fallback.

## Shared visibility

- Preserve live user edits, existing IDs and links where feasible. Snapshot before mutations. Separate explorations from approved frames and implementation. Never overwrite another team's frames or import its private direction.
- One Figma writer integrates changes. Specialists return node-specific findings or render annotations. Link actual working frames/pages so the user can inspect progress.
- Prefer editable text, vectors, components/tokens and charts; use approved authentic assets. Rasterize only when justified and retain quantitative data/specifications.
- Inspect native renders, bounds, contrast, spacing, source rows and navigation. Keep essential caveats with claims; use concise linked title/publisher source labels.

## Web-to-Figma agreement

Map approved frames/states to routes/components. Figma establishes design intent; the rendered application establishes behavior. Compare final application screenshots at corresponding sizes and record intentional deviations. A Figma render does not replace browser verification; a screenshot pasted into Figma does not establish editable native design.

- **`figma-port` (Figma node or exporter -> existing tokenized codebase):** When implementing or restyling a component or page from a Figma URL/node or exporter snippet (`FireJet`, `Anima`, `Locofy`, `builder.io`), load `../figma-port/SKILL.md` to verify `get_variable_defs`, run the Phase 2 `D-NNN` ruling-check (`coordination/decisions/`, `docs/`, `tokens.ts`), and classify every diff into Bucket `A` (render loss), `B` (unruled drift), `C` (content/data-model blocker), or `D` (ratified decision conflict) before editing CSS or markup.
- **`brand-design-audit` (greenfield brand or pre-scaffold intake):** When starting a new brand or client site before an approved Design Direction Brief exists, run `../brand-design-audit/SKILL.md` first (trademark pre-check, palette/WCAG verification, and claims-integrity check).
- **`web-motion-protocol` (scroll, reveal, or micro-interaction motion):** When a Figma prototype or brief specifies motion, enforce `../web-motion-protocol/SKILL.md`'s 7 hard gates (`CLS = 0`, `LCP < 2.5s`, `INP < 200ms`, `< 20 KB` critical bundle, `prefers-reduced-motion`, and tall-viewport `min(100vh, 64rem)` stage caps).

## Presentation gates

Reuse structure without prior-client branding, numbers, personas or private links. Include cover, section structure and minimal tracker/navigation when appropriate. Keep a dedicated source area separated from body/navigation. Adapt spacing to format, not one deck's pixel values.

Inspect every slide's fresh render, hierarchy, margins, padding, wraps and bounds. Verify chart/data agreement, units, denominators, dates, assumptions, legends and color meaning. Decorative curves carry no trend claim. Essential caveats survive copy shortening. Verify descriptive external links and internal navigation. Do not expose private workshop URLs or broaden permissions for sharing.

Inspect the actual requested PDF/PPTX export: order, fonts, cropping, chart fidelity and clickable external/internal destinations. Link count alone is insufficient: validate target and bounds. Distinguish structural export checks from native-application tests and disclose limitations.

Authoring/export code follows full 4D and applicable blind review. Native-slide edits do not acquire meaningless code metrics. Keep client evidence separate from reusable template resources.
