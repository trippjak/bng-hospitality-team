# UX/UI Team

Deliver a coherent, usable artifact with evidence tied to the final version. Read project
instructions/state and capture the audience, primary task, artifact/format, brand authority,
references, preserved behavior and checkable acceptance criteria. Distinguish creation,
revision and comparison; resolve material unknowns without repeating answered questions.
Fit the existing stack. Keep client facts, assets, credentials, source ledgers and outputs in their workspace;
reuse template structure without transferring client identity or claims.

## Staff and choose

Argon leads design/implementation; verify a callable route before dispatch. If unavailable,
report the blocked seat and continue independent preparation only until access or an explicit
lead substitution is resolved. Honor user model overrides. Use a fresh native agent for
independent UX/UI QA; the lead cannot approve its work. Disclose an unavailable QA gate.

Keep one integration writer per shared surface; respect disjoint ownership. Dispatch relevant
specialists in parallel when useful, not to fill a roster. The host coordinates tools/evidence
and confirms the final artifact. Do not install a dispatch framework. Hugging Face specialists
are not a default sketch stage, reviewer, fallback or rewriter; keep experimental arms isolated.

For a new brand or substantial redesign, present two distinct directions before substantial
implementation and let the user choose. An approved direction needs no new checkpoint;
an explicitly AFK run permits a choice against the brief with the reason recorded.

## Deliver and verify

1. **Baseline:** pin revision, protected behavior, references, tool/model identities, acceptance
   checks and fresh baseline renders. Reconcile narrative, interaction and visual system in a short brief.
2. **Build:** the designated writer implements the direction in the real stack/native artifact.
   An isolated sketch is a visual reference, never merged wholesale. Independent QA inspects
   fresh renders and exercises interactions; preserve initial findings.
3. **Repair:** run project checks, all applicable measured 4D dimensions and required blind review.
   Consolidate functional, visual and code findings into one repair batch. Behavior-preserving
   cleanup also follows the ratchet contract; shorter code cannot justify weaker behavior or visuals.
4. **Confirm:** rerun affected functional checks, all applicable 4D dimensions and required review;
   substantive code repairs need fresh blind review. QA verifies repairs, then the host inspects
   final renders and the actual export/authorized preview. A lead's summary is insufficient.

One repair-and-verification cycle is the default; further substantive defects require an explicit
replan or held result. Preserve client requirements and required CI without redundant review panels.
Subsequent edits invalidate affected evidence; reuse only with verified matching inputs.

## Boundaries and close

Use only isolated headless testing of the designated preview as specified in acceptance:
no desktop capture/control, personal sessions, unrelated tabs or live customer actions.
Figma connector/API work supports visibility without desktop control. Authoring grants no
broader sharing, production deployment, merge, paid hosting or additional-provider export.

Return the artifact link, changes, acceptance status and limitations. In existing project
evidence retain baseline/final revisions, roles, direction, tool/model identity, criteria,
initial findings/repairs, check evidence paths and held gates; retain useful decisions for the next iteration.
Distinguish authored, reviewed, local/hosted verified and released. Installation or a dry run
does not establish interface acceptance; trivial work needs no ceremony files.
