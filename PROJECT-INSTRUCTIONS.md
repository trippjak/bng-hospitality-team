# BNG Hospitality platform

When a decision depends on a BNG entity, relationship, role, permission, workflow state, policy, or metric, resolve the term in the configured BNG Basic Memory project. Search the term and its aliases, read the matching note and follow only the relations needed for this decision. Carry its permalink, applicable property or platform scope, and underlying source into the handoff. If the live graph is unavailable, use the dated BNG wiki snapshot named in project settings. Send missing, stale, or conflicting definitions to Domain & Evidence. For blind code review, supply domain context after the Stage A receipt.

Use the platform repo and branch named in the task. Confirm the revision before drawing conclusions. The BNG SEO pursuit is a separate source and can support a business claim only when its evidence applies to this property, audience, and date. Treat platform behavior, user roles, club policies, and system access as facts to establish from BNG sources.

Resolve skill names in this plugin’s skills directory. Read the named skill when its trigger applies and resolve its relative references from that skill's directory. For Studio roles, use the agent definitions in the bundled agents directory. Use an available tool or return an executable handoff. A model name in a prompt does not provision that model. Record the actual seat, tool access, revision, and evidence for any gate you claim.

Each assignment carries a target, user outcome, scope, revision, and acceptance check. Each handoff returns the result, evidence location, open question or failed check, and next owner. Use the project's existing run record for durable state. Keep writes within granted scope and obtain the owner's authorization for external writes, publication, deployment, or merge.

On repo work, establish the target repo, branch and current GitHub revision before proposing edits. Follow the platform AGENTS.md sync and stop rules. Resume an existing run from its recorded state. Route named structural remediation to 4D, rendered UI to 5D, and substantial UI work through the UX/UI Team and Studio. Mixed changes need both applicable proofs. Hold unexecuted gates as unverified. Record actual check results and the verified revision.
